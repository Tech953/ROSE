# Rose 0.8.0 validation

## Completed verification

**169 Python tests pass.** The real-HTTP interface flow and native canvas checks also pass with the final reference-v5 atlases. These results cover the shipped prototype and the checks below; they do not establish full browser or Windows compatibility.

- The Blender 4.2.0 Cycles CPU bake contains **46 source models and 1,244 raw frames**: five anatomical body families and one construct with 192 frames each, 28 regional infrastructure models, four obstacle prefabs and eight modeled field/path fills. All eight body actions have six registered facings. Every raw frame passes the exporter’s mesh/shadow clipping check or opaque central ground-sample check.
- **120 indexed PNG atlases register 132 game entries** with the same 256-entry palette: transparent index zero, sixteen graded black-shadow slots and 239 opaque color entries. Seventy-four atlases are two additional palette treatments of existing models. They preserve every alpha value; they are not additional meshes. All five body families have distinct rendered pixels and silhouettes, and all 28 buildings have visibly different healthy/worn frame pixels.
- Native character cells are **192 × 192**, scenery **288 × 336** and ground fills **192 × 240**. The inverse **2/3 drawing scale** preserves world size and registered foot offsets. Scenery retains its transparent shadow margins; collision cells do not grow. Camera projection, six facing directions, frame origins and complete action clips are checked. Body/scenery renders use native resolution with 48 jittered Cycles samples and denoising; ground renders use 2× resolution so the central opaque relief crop is not enlarged during export.
- Twenty-one art-pipeline tests verify projection, the unique 1–1,244 timeline, complete clips, opaque-black safety, palette learning, deterministic alpha coverage, all sixteen shadow grades, identical palettes/transparency tables, atlas bounds, opaque ground, source/output checksums, previous-pack preservation, world registration, distinct body silhouettes, tone alpha, building wear historical/current body-source provenance, v4 preservation, unchanged current body PNG bytes and distinct opaque regional paths.
- Nine visual-designation tests verify old-template migration, rejected presentation values, independent stats/pronouns, automatic Metal-kin selection and explicit presentation, stable travel/recruitment/JSON identity, condition-independent structure identity, sector-qualified IDs, complete profile/region registration and matching player/unit identity in the first host snapshot. Visual inspection does not change simulation RNG or collision geometry.
- All 92 environment frames were freshly rendered from the final saved source in two matching shards, with three CPU threads per process. The 1,152 body frames retain the exact preserved v4 source/recipe provenance after before/after dependency checks. The fingerprint includes material nodes, geometry, pose curves, body camera, sampling, sunlight, area fill, ambient, shadow floor and color management. Strict composition rejects mismatched source/settings identities, altered registration, incomplete proofs, duplicate/missing models and unsafe paths. Receipts include actual per-model source hashes. The original 3D, grounded-v2, individual-v3 and fidelity-v4 source recipes and atlas bytes remain preserved; current body/treatment PNGs match their v4 bytes.

No reference-sheet pixels or meshes are shipped as Rose assets. Final image integrity checks decode and verify all 408 project PNG/GIF files, including historical art and previews. An incomplete prefab preview was regenerated; image publishing now replaces each final target only after encoding completes.

### Interface, display and loading

- Native canvas checks render each of the five selected body families and verify the selected sprite’s alpha picking. They check regional asset resolution, original-bank fallbacks, healthy/worn changes, stable designations and unchanged host state. Drawing, bounds, selection and foreground fading resolve the same asset and current frame. Selecting a person, structure or obstacle also draws that current asset in a read-only **360 × 360 appearance canvas**; selecting empty ground hides it. Tests check real decoded pixels, structural appearance and unchanged simulation state. Native path checks verify that full and separately clipped draws share identical pattern coordinates in every region, and that existing tile designations visibly select path surfaces without spending resources or changing host state.
- The earlier 0.6 sprite-loading diagnostic started 134 image requests at once; a diagnostic run observed connection delays exceeding 14 seconds. The loader now shares a **six-image queue** across banks and caches each URL. Its regression checks bounded requests, alias reuse, complete readiness, independent banks and continued queue progress after a decode failure. A diagnostic of the complete interface flow after the fix recorded no image response taking over two seconds. Those timings describe this local run, not a performance guarantee.

Host-flow checks verify native label settings and painting order, unchanged picking/world state and stored preferences. Reduced-motion and blocked-storage paths are exercised.
- Local interaction checks cover cursor cycling, no-roll hover, held-menu suppression, keyboard/touch fallback controls, blocked-action conservation, default Look, one-click movement, discovery preferences, room changes, civilian rejection and combat prerequisites. Native pixel checks verify transparent padding, real foreground overlap, changed fade pixels and picking through to a covered character.
- The actual renderer exports field, world and interaction panels at **1000 × 620**, plus the enlarged appearance canvas. The display comparison is assembled from the same frozen field in Sharp Pixels and Soft Phosphor. Prefab panels and the eight-frame, six-facing walk preview use shipped indexed pixels; the GIF composites translucent shadow slots against its neutral background. ## Reproduce the checks

From the `rose` folder:

```sh
python -m unittest discover -s tests -v
node tests/ui-smoke.cjs
```

The interface test uses Node built-ins, a modeled DOM and the actual Python HTTP host. Its companion files exercise assurance, interaction, audio, display, individualized visuals and sprite loading. If `@napi-rs/canvas` is available, it also decodes the actual atlases, checks native pixels and exports previews. Without it, drawing checks are explicitly reported as skipped. Pillow enables the developer art checks. Node, Pillow and Blender are not required to play the exported graphics. See `3D-SPRITE-PIPELINE.md` for complete render/export commands and historical source records.

## Remaining validation and production scope

A browser executable was unavailable for full Chrome/Firefox testing. Browser layout, live touch gestures, audible playback, screen-reader use, Windows launch, real multiplayer over a LAN and large-world performance still need live playtesting. The Windows batch launcher is supplied as source; no native EXE or installer is included. The optional model adapter has mocked-response checks; live model inference was not run.

The five original body families have individual proportions, faces, clothes and costume equipment; shared families can recur across NPCs. Written appearance stays registered for dialogue but does not generate a new sculpt. Decorative gear does not grant inventory or permissions. Bespoke likenesses for every named character, inventory-matched weapons, firearm-specific animation, sculptural talking portraits, expression/lip sync, voice acting and a finished third-game story remain production work. The current assets are tactile pre-rendered prototypes, not finished photorealistic human scans. Soft Phosphor is an art display profile, not a calibrated physical CRT simulation.

The source world documents continue to inform interpreted geography and motifs. The uploaded Fallout references inform the controls and art direction; numerical rules and generated infrastructure remain Rose adaptations.
