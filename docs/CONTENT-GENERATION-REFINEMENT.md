# Shared content foundation 1.0 — systems update

Released 2026-10-18 for Thorns 0.5.0, Stem 0.4.0 and Rose 0.19.0.

## Result

A single Python-standard-library generation module now runs in all three games. Stable site identities and regional surface recipes support detailed descriptions without re-rolling a location's identity whenever its weather changes. Dialogue varies through a saved, player-specific sequence and refers to observed attempts, local needs and existing character records. Rose exports the content schema and each site's presentation record with its infrastructure blueprint.

## Playing the update

In Thorns, create or resume an Open world room. Ordinary sites now expose six local-contact topics: Place, Needs, History, Access, Contracts and Plans. A generated contact remains the same person when you return. Conversation keeps the public facts available on failed checks. It spends no supplies or XP and creates no permission. A good handover can improve trust once per four movement steps; repeatedly clicking a topic cannot farm it. Received projections cannot spawn ordinary contacts.

In Stem and Rose, use the existing `ask about ...` controls and companion conversations. Work near a resident or traveler, then ask about history or plans. An NPC can recall the recorded repair attempt, planting, submission, care or supply handover. Only people present in the same survey sector receive a witness record; no remote journal or chat is imported into their knowledge. Local hex occlusion is not a simulated limit on this sector-level memory.

## Source and aesthetic scope

The four regional recipes use the supplied regional documents and the established Rose art-direction register. WN_TOWER keeps weathered service metal and bio-plast; CITY_CLOUD_S uses repaired mountain metal and mineral surfaces; ENACT_HILLS retains inhabited foothill craft; AETHERGALE uses wind-scoured surfaces and small crystalline accents. Existing source character biographies and uncertain fates remain intact. New surface details and contacts are explicitly adaptations.

Descriptions respond to moisture, structural stability, shelter, weather and time of day. A dry site is not described as wet, and night does not manufacture a powered fixture. Growth, resources, threats and construction still come from their respective simulation systems. New sensory detail describes existing features rather than creating an interactable building or supply. Whole monument scale and map distances are not inferred from a surface recipe.

The shared module does not operate game actions, grants, dice, cargo, power, collision or physics. Optional local-model prose receives the shared content context; Rose's hidden particulate and optical measurements are excluded from that optional context. The local model remains an optional fallible prose adapter. No external model endpoint was used for validation.

## Save and memory behavior

Migration is additive and idempotent. Existing position, character, biography, stocks, credentials, relationships and clocks survive. Site descriptors use keyed SHA-256 choices independent of Python's randomized hash and of generation order. Text rendering is pure. A dialogue action alone advances its presentation counter.

Each player retains up to 64 active NPC/topic variation counters. A witness keeps the latest 12 observed attempts. Existing dialogue ledgers retain their previous limits: 200 player records and 40 companion conversation records. Older records are intentionally bounded rather than claimed to be infinite memory. Thorns stores up to 2,048 visited site descriptors and blocks a new visit once full; revisiting existing sites remains available. Thorns contacts remain tied to ordinary sites, not to remote projections.

## Mechanical correction

Thorns open-world practice now caps training and eligible equipment together at +2, matching its chapter rules and the Stem/Rose foundation. New contact checks apply local faction standing, conditions, relevant skill and experience. Natural 1/20 behavior remains authoritative. Failed conversation checks preserve public information. Creation text cannot grant credentials.

## Fidelity and remaining production work

This release improves the fidelity of prose and persistent characterization. Existing raster assets and Blender sources are preserved byte-for-byte; documentation previews can be regenerated by interface tests. New unique meshes, sprite-sheet bakes, inventory-matched body layers and sculpted portraits remain production work. The fixed isometric presentation, continuous scenery, hidden local hex movement, CRT preferences and established lighting banks retain their existing renderer.

Thorns' legacy credit economy and the prototypes' material-price exchanges remain numerical adaptations. They should not be read as canon currency in the Fourth Corners, where the author's current rule is contracts, provision and actual resource obligations. The tabletop edition uses that current rule. Save databases are game-specific; this shared module does not merge characters or saves between engines.

## Verification

Thorns: 36 Python tests passed, including contact persistence, restricted projection behavior, bounded site saves, practice and reputation arithmetic. The contact UI harness verifies all six action buttons and the retained reply using real server public state. Existing HTTP/session/voting checks remain in its suite.

Stem: 81 Python tests passed. The real-HTTP interface harness passed creation, two companions, dialogue, contracts, businesses, infrastructure, combat, routes, projection boundaries, pause and recovery.

Rose: 451 Python tests passed. Its interface regression uses six isolated flows for the core game, art direction, materials, weather, animations and particle interactions. See the accompanying validation receipt for final flow status. Native-canvas exports exercise rendering; these are not a full-browser layout or human gameplay balance test.

Shared checks cover stable identity, dry/wet rendering, pure description, repeat variation, save/reload equivalence, failed checks, source-biography preservation, personal witness scope, remote exclusion, bounded histories, and hidden-measurement exclusion. The three installed generation modules have identical SHA-256 hashes.
