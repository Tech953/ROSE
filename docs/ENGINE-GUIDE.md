# Rose engine guide

**Version 0.11.0 · world engine schema 1 · blueprint schema 1**

The engine separates source-world anchors, seeded generation, persistent state, action resolution and visual presentation. The supplied atlas fixes regional relationships and named places. A seed and saved rules determine local infrastructure and hex fields. Player and autonomous actions change those persistent records. Prepared art expresses the records without writing back into the simulation.

## Hidden local hexes, movement cost and range

Local field positions are axial hex coordinates, hidden during ordinary play. **HEX GRID** reveals the overlay when wanted. The fixed isometric projection and between-cell animation describe those positions on screen; submitted movement and action targets resolve to registered cells or object IDs. Pixels do not determine combat range.

A move commits one of six adjacent cells after the host checks passability, occupancy, turn ownership and AP. The default combat movement cost is **1 AP per hex**, configurable to 1 or 2 in the saved world rules. Route previews count actual walked steps, including detours. Outside combat, movement spends energy and applies one survival/ecological cycle per six local steps, with no combat AP charge. Each step retains the existing skill/context/standing check.

| Local action | Authoritative spatial rule |
| --- | --- |
| Walk | One adjacent passable, unoccupied hex per committed step |
| Staff strike | One visible hex |
| Crystallin shot | One through six hexes, clear line of sight, registered weapon/ammunition |
| Construct negotiation | Within four visible hexes |
| Selected resident conversation | Within two hexes of the registered resident |
| Generated structure work / public-stock access / exchange trade | One adjacent hex beside the target structure |
| Companion make room | Adjacent companion; one free neighboring destination, plus willingness and check |
| Look / sensory observation | Registered scene target; read-only observation can use labelled remote scope |

Direct range uses cube distance: `max(abs(dq), abs(dr), abs(dq + dr))`. Walking uses routes through neighboring cells, so a detour can cost more AP than direct target range. Line-of-sight checks traverse intervening hexes and reject opaque barriers. Cover, inventory, credentials and skill/context/standing checks then add their own prerequisites and outcome rules.

The overworld remains continuous point travel with selectable destinations and explicit local entry. This local hex system applies inside each location.

The original Fallout manual, printed page 5–3, Table 5-1, lists walking at one AP per hex; the same page describes movement-cursor cost feedback. This provides a primary reference for the local AP convention. Rose's weapon ranges, survival costs and interactions remain its own rules. [Original Fallout manual](https://shared.fastly.steamstatic.com/store_item_assets/steam/apps/38400/manuals/Fallout_manual_English.pdf?t=1572025441).

The Balanced profile uses host defaults. Frontier lowers density, population and condition while raising hostility. Settlement increases public-works density and resident demand while lowering hostility. The editor shows the selected profile's full rules and permits bounded overrides.

## Infrastructure records

A generated node contains `id`, `kind`, `name`, axial `pos`, `condition`, `enabled`, `material`, `faction`, `capacity`, `status`, `work_serial`, `repaired_by` and a bounded ledger. Links join nodes with a condition and a contiguous hex path. The network is an undirected spanning tree; power reaches enabled nodes with condition at least 30 through links with condition at least 30.

| Module | Input / prerequisite | Effect |
|---|---|---|
| Wind collector | Maintained, enabled root; wind abstraction | Adds bounded power. |
| Cistern | Connected power; actual local water; store space | Transfers up to capacity local water to public stock. |
| Cultivation frame | Power, public water, actual local food, growth at least 20 | Transfers local food to stock, uses equal water and one growth. |
| Workshop | Power, actual local scrap, store space | Reclaims one local scrap into public stock. |
| Refuge | Maintained physical shelter prefab | Provides an accessible shared structure; inherited sector shelter rules continue separately. |
| Exchange | Maintained, enabled building and adjacent character | Enables finite shop transactions. Food/water restock transfers from public utility stores. |
| Relay | Connected power and successful operating cycle | Supplies +1 local check context while its operating network remains connected. |

Production prioritizes water, cultivation and relay before other powered demands. Resident water demand is `ceil(population / 8)` and food demand is `ceil(population / 12)`, with a minimum of one. Actual consumption is limited by stock. The ledger records conversion and shortfalls; it does not create unaccounted goods.

Each player's successful repair spends one scrap, restores 25 condition, reinforces adjoining links by ten and increments the node's work serial. An autonomous NPC repair spends one NPC scrap for 15 condition after reaching an apron; it does not satisfy another character's personal maintenance contract. Agreement validation uses actor identity and a later work serial, preventing earlier repairs in the same cycle from being credited again.

The legacy habitat, shelter, public water apparatus and relay actions remain as sector-scale adaptations. Generated structure interactions use physical positions and the utility network described here.

## World and time model

The overland atlas uses interpreted survey sectors underneath a continuous world position. `player.overworld.point` is fractional; `player.pos` identifies the current bodily sector. World routes use eight directions, terrain-weighted Dijkstra search and explicit diagonal barrier checks. A bounded one-second host update advances at 2.4 seconds per base world unit, multiplied by terrain cost. Sector boundary crossings apply survival and traversal checks exactly once; movement to another point inside the same sector does not recost that crossing. Local scenes use axial `(q,r)` coordinates with six neighbors and cube distance. These coordinates describe different scales, and neither asserts a measured distance from the source photographs.

The saved navigation record includes mode, status, current point, target, serial, bodily sector, visited sectors and viewed sectors. Arrival remains in world view until explicit entry. Stops retain the exact current point and route. Health at most 30, energy at most 15, or thirst/hunger/sleep at least 80 halt automatic travel. A hostile crossing enters local combat and retains the onward route; resume remains an explicit player choice after care or encounter resolution.

Opening the world map does not stop travel. Resume recomputes the terrain-safe path from the current sector before updating the journey. Recovery, including recovery at the spawn itself, and field relocation clear obsolete targets and routes. Ordinary stops preserve fractional position.

Shared pauses, remote observation and any active combat suspend travel. Host-clock movement increments the room revision, so stale redirects cannot spend resources or replace a newer route. A disconnected browser retains its seat and journey; the host continues the saved journey while the room is active. Rooms idle for five minutes suspend autonomous processing. Server restart resumes an unfinished journey when the saved room becomes active again. No wall-time catch-up is charged after shutdown.

Discovery is per player. The cartography overlay is presentation-only and cannot mark visits, generate NPC knowledge or award resources. Numeric coordinates and the named selector provide keyboard alternatives to canvas clicks. Older Rose schema-1 saves receive an idle navigation record at their current sector, preserving their route without silently starting travel.

Local walking always commits one adjacent hex. Six local steps apply one inherited survival/ecological cycle. Each step also spends one energy, or two after a failed footing check. Long click routes are a sequence of these authorized steps and stop on an encounter or failed request. NPC following also respects physical paths and occupancy.

The client serializes polls, rejects replies from an earlier session or preceding an action, and resets field/world view caches per room and player. Disconnect cancels remaining local steps. An action already sent can still commit once on the host; mutations are never retried automatically. Temporary host response failures preserve the typed input. Storage failure leaves the live session usable without claiming it has been remembered.

Automatic travel/ecology exceptions quarantine only the affected active room and expose `clock_error` in its snapshot without changing the simulation revision. The client therefore also watches that field. Host pause/resume clears the quarantine for an explicit retry. SQLite save transactions roll back on failed writes; unfinished in-memory tick work is not saved.

Encounter initiative combines Body, Percept and a bounded seeded roll; successful detection adds two for the initiating character. AP refreshes when a living participant becomes current. Human turns wait for input; NPC and construct turns execute their own physical movement and checks. Companion willingness and care requirements are rechecked on their turns.

The shared ecological clock holds while any encounter is active. Ordinary actions elsewhere can still apply their own personal costs, but automatic growth, resource cycles and roaming migration hold. Ending your own turn applies one personal survival cycle. Host advancement of a guest turn does not spend that guest's personal needs. The last encounter's resolution resumes shared time with one ecological cycle.

| `companions.py`, `adventure.py`, `institutions.py` | NPC cycles, dialogue, commitments and finite exchanges | Lore stays stable; engagement records change through actual events. |
| `server.py` | Seat authority, revision checks, SQLite persistence and world clock | Failed operations retain the last saved state; tokens are never public scene data. |
| `static/scene.js` | Field rendering, selection, path previews and controls | Do not infer new inventory, injuries, permissions or check results in the renderer. |
| `static/ui.js`, `static/app.js` | Session/poll authority, storage fallback, stable interactive state and control locks | Keep presentation state separate from game records; disabling controls never substitutes for server validation. |

| `static/prefabs.js`, `static/art-manifest*.json` | Four selectable art styles and replaceable sprite clips | Keep foot origins, action names and each style's image bank consistent with the registered field. |
| `static/audio.js` | Original procedural field cues | Require explicit enable and retain text/visual feedback. |
| `narrator.py` | Optional loopback descriptive prose | Decorative model output cannot mutate the world. |

The shared D20 resolver remains `attribute + training/equipment + experience − conditions + fatigue + reputation + context + trust + attitude + nearby companion support`. Natural 1 fails; natural 20 succeeds. The UI exposes the component record. All accepted game interactions produce checks; rejected prerequisites, unsupported input and session administration do not create a game turn.

`scene.action_availability` supplies read-only allowed/reason records for tactical controls, including host turn advancement. It reports current prerequisites without rolling dice or spending AP. Every action handler repeats its authoritative checks at submission. `scene.interaction_options` binds actual targets to Look/Use/Item/Skill intents, training, base difficulty, costs and blocked reasons. These catalogues do not roll or spend. Field-specific intents use the object menu and bounded text parser; the optional model interpreter keeps its previous reviewed action set. A permitted attempt can still fail its skill check or become stale before reaching the host.

## Art and future scene content

The default rendered style uses 1,244 Blender Cycles frames from 46 models, exported to 120 indexed PNG atlases in one common palette. Five anatomical field-body families and the construct each have eight actions in six directions. Seven infrastructure functions have four regional constructions with healthy/worn clips. Each model keeps the fixed cell, scale and foot origin matched to the scene's 0.52 ground compression. Stable visual designation selects a body, regional model and prepared palette treatment; role rings retain their existing meanings. The earlier 3D bake, material prefabs and vector manifest/source/preview remain selectable without changing simulation state. The current bake uses five body families and regional construction/condition models. The v1, v2, v3, v4 and v5 source recipes and atlas files are preserved. `visuals.py` assigns stable actor and sector-qualified structure designations without using simulation RNG. `static/visual-catalog.json` is shared by character creation and authoring. All drawing, masks, bounds and fading resolve the selected asset and current frame. Each raster style has a separate manifest and image bank. Failed image loads retain the vector fallback. `static/display.js` provides optional Soft Phosphor sampling, static scanlines and restrained glow before native labels/selection outlines. Sharp Pixels and CRT Off bypass it. Its buffers are reused; display choices never mutate scene geometry or game state. See `ART-DIRECTION-AND-DISPLAY.md` for settings and the separate portrait production plan.

`tools/render_blender.py` builds the original procedural meshes and keyframes; `tools/render_saved_blend.py` renders edited source geometry; `tools/export_sprites.py` downsamples and packs a common palette. The editable source and production settings are in `art-source/`. See `3D-SPRITE-PIPELINE.md` for registration conventions and rebuild commands. The existing `tools/build_art_manifest.py` still registers the preserved image-generated style without editing its source sheets. Blender and Pillow are authoring dependencies only.

The first editable pre-rendered asset set is integrated. Sprite alpha now supports depth-aware picking and foreground prop fading, without changing saved passability, cover or line of sight. Detailed interiors/roof groups, doors/containers, limb-specific attacks, inventory-matched weapon layers, bespoke faces, portraits, terrain streaming, authored sound recordings, voice and cinematics remain production work. Short opt-in procedural cues are included. Adding scene content does not require replacing the saved infrastructure model or shared combat scene. See `LOCAL-INTERACTION-GUIDE.md`.

World capacities remain six human seats, two companions per player, 24 roaming NPCs, 28 source landmark custodians, 2,048 discovered sectors and 100 saved rooms per host. Local radius is bounded to nine. Large-world performance and internet deployment have not been benchmarked. Source images remain accessible; the inherited conversion notes are in `stem-foundation/MAP-CONVERSION.md`.

## Detailed field graphics

The 0.7 bank increases native image cells by 50% and draws them at inverse scale, retaining the same registered hex positions and foot origins. Sixteen graded shadow levels reduce stippling. Selecting a person or structure opens a read-only view of its actual current appearance; it uses the current asset, facing, action and condition. Art, visual designation and written appearance do not grant inventory or change skill checks. Earlier sources and atlas bytes remain preserved.

The reference geometry and four regional path surfaces remain the basis of the current spectrum bank. All clipped path tiles share a global pattern origin. Cached canvas patterns reuse the loaded asset and context. The 1,152 raw body frames, source dependencies, registration and alpha remain preserved, while RGB is reindexed into the new v6 palette. Ninety-two environment frames are newly rendered with regional material response and practical lighting. Decorative cladding, wrapping and tools remain part of each structure sprite. They add no loot, collision, cover or permissions. See `PREFAB-REFERENCE-GUIDE.md` for all supplied-sheet mappings and production limits.

## Powered optical framework

`photonics.py` owns the bounded reservoir, synthetic material spectra and controller. Its field-owned records persist under `substrate.fields[address].photonics`. Individual particle imports cannot supply optical energy. Tuning requires an adjacent maintained workshop and a Light check with normal context/standing modifiers. Existing `particle_excite` spends one actual public power and records its optical input even on failure. This ledger is independent of the existing particle kinetic heuristic. See [resonance and sources](RESONANCE-AND-SOURCE-GUIDE.md) for exact rules and source boundaries.


### Physical optical controls in 0.11

Workshop context actions reuse `particle_survey`, `particle_tune`, `particle_excite` and `particle_quench`. A tuning target is `workshop-id|band:mode`; other bound targets carry the exact workshop ID; `particle_audit` adds a cycle-free registered audit. Untargeted text commands retain their syntax. All physical controls now require an adjacent maintained workshop. One live source serves each field reservoir; rebinding requires a cold reservoir. The request envelope permits up to 80 target characters for these five registered operations, while other action targets retain their 30-character limit. Ordinary request-body and particle-import limits are unchanged.

Read-only prerequisite helpers use actual network connectivity. World ticks reconcile the source again after infrastructure wear and companion work, without a second emission or input. Automatic shutdown retains binding/settings and transfers energy to heat; recovery never pumps automatically. Workshop ledgers attribute optical attempts without issuing repair work serials. Menus and inspector use the same host guards. Schema 1 saves continue to load without a destructive migration.


### Proposal provenance and audit journal

`research.py` loads `reference/research-protocol-v011.json`, computes the finite optical ledger's normalized residual and records up to sixteen audits under each field's `photonics.research_runs`. It does not implement the proposal's DTC, relational, TCE, reuptake or representation dynamics. Gates always originate from the server-owned protocol and remain Not Run; source imports cannot replace them. `particle_audit` uses a Perception/Light check, records actor/source/seed/field/version/units, preserves travel/combat turns and spends no cycle or resources. `research_export` reads the latest complete record without a revision change. The exact source PDF is served through a fixed route, rather than a general filesystem endpoint. Schema 1 worlds without journals load with empty histories. See [VREX-INTEGRATION-GUIDE.md](VREX-INTEGRATION-GUIDE.md).
